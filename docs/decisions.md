# Decision log

## 2026-07-09 (session 13 — E2E wiring PR-A: streaming seams)

Owner directive: work through the remaining STATUS.md tasks autonomously (/loop). First unblocked task: the STT+format+paste end-to-end wiring, split into PR-A (KoeCore/Providers seams, CI-verifiable) and PR-B (App composition root, owner-QA-gated).

- **`AudioCapturing`/`Transcribing` seams reshaped from batch (`Data`) to streaming (`AsyncStream<Data>`).** The M1-T2 batch shape would have buffered the whole utterance and only then contacted STT — every utterance would pay its own duration again after key-up, structurally breaking the §10.3 `sttFinalTimeout` (2s) ladder for any real sentence. Chunks now flow to STT while the user speaks (matching how `AudioCaptureEngine` and `SpeechmaticsClient` already work); `Transcribing.transcribe` gains an `onRecordingEnded` callback so the coordinator advances the state machine at true end-of-speech, not at transcript-complete.
- **`UtteranceContext` now carries `recordingBundleID`, captured per utterance at press time** (closes the M5-T2 review prerequisite). `SessionCoordinator` takes a `ContextProviding` collaborator and captures `frontmostBundleID()` in `startUtterance()`; `LLMFormatter`'s `frontmostApp` live-read closure is deleted (same signal, but a live read races overlapping utterances and, if ever pointed at the `@MainActor` provider from the pipeline task, is a crash hazard). PR-B consumes the same field in `PasteSimulator` and removes its closure.
- **New `STTTranscriber` (KoeCore) adapts `STTClient` behind `Transcribing`, with a finals-tail circuit breaker.** New `KoeConstants.sttStallTimeout` (30s) + `STTError.timeout`: bounds key-up → transcript-complete only (NOT the recording leg — a deliberate deviation from the first design sketch, which bounded the whole `transcribe` call and would have killed any utterance longer than the bound; recording length is the user's, capped by `maxSessionRecording`). Without this, a dead socket that accepted audio but never confirms end-of-transcript wedges that utterance's FIFO ticket forever — and with it every insertion behind it (a full-app freeze class, distinct from M4-T3's 2s-resend UX which stays blocked on M9). On cancellation the transcriber re-checks `Task.isCancelled` before returning a stream-terminated transcript so a cancelled utterance can't insert a truncated result.
- **`SessionCoordinator`'s catch-all now logs `utterance_failed`** (was completely silent — no signal at all when an utterance died end-to-end).

### PR-A high-effort code-review follow-up (6 findings; 4 CONFIRMED fixed, 1 cleanup applied, 1 declined)

- **`onRecordingEnded` is now exactly-once on EVERY exit path** (the review's top cluster). Three related holes: (a) a provider that finalizes before key-up let `.transcript` win the race before the feeder fired the callback — the session stayed `.recording`, `receiveFinalTranscript` threw `illegalTransition`, and a *fully transcribed* utterance was dropped with no history row (invariant-1 violation; the scripted test double had masked this by only yielding finals from inside `endUtterance`); (b) a mid-recording `send` failure skipped the callback entirely, breaking the documented exactly-once contract; (c) the coordinator's `try? await session.endRecording()` silently discarded state-machine errors. Fix: a private `Once` actor in `STTTranscriber` fires the callback on normal end-of-speech, early finalization, and every throw path; the coordinator's callback logs `end_recording_illegal` instead of `try?`. Regression tests for (a) and (b) + seam doc updated.
- **`AudioCapturing.record` now returns `AsyncThrowingStream<Data, any Error>`** (was `AsyncStream`). A silent `finish()` on a mid-capture fault (device died, HAL error) is indistinguishable from key-up — the pipeline would transcribe and insert a truncated utterance as success. A fault must throw, failing the utterance loudly (invariant 1). The engine-side mapping of route-change failures onto stream errors lands with PR-B / the M9 `onCapReached` callback split.
- **`startUtterance` parallelizes the focus read and ticket reservation** (`async let`) — they're independent hops; press-order ticketing is the caller's await-per-press contract, not intra-method ordering.
- **Declined: replacing the finals-tail race with `Deadline.run`.** The tail deadline starts mid-race (at `.fed`), not at operation start — `Deadline`'s shape. Restructuring event consumption into two sequential phases to fit it would cost more than the duplication; a comment in `STTTranscriber` records this.
- 174 tests green (10 new vs. main). `/verify` deferred to PR-B: these seams have no app-reachable runtime surface until the composition root wires them (nothing in the running app changes on this branch).

## 2026-07-09 (session 13 — M4-T3: batch resend + retry)

- **`ResilientTranscriber` implements the §10.2 ladder around the streaming adapter**: tee chunks into an in-memory tape → streaming attempt (finals tail bounded by `sttFinalTimeout` 2s when composed by the app) → on failure, wait for the mic stream to SETTLE (complete vs fault) → one batch resend → double-fault persists the WAV and throws `UnrecoveredUtterance(audioID:)`. Two deliberate choices: (a) the tape pump outlives the streaming attempt, so audio spoken AFTER the socket died is still resent (zero text loss; fault-injection test asserts the WAV contains post-failure chunks); (b) a mic-side fault is NOT resent — incomplete audio failing loudly is the PR-A/B contract, resending it would insert a truncated utterance as success.
- **Batch adapter**: `SpeechmaticsBatchClient` (`POST /v2/jobs` multipart `config`+`data_file`, poll `GET /v2/jobs/{id}` at `sttBatchPollInterval`, `GET .../transcript?format=txt`; docs fetched 2026-07-09). Invariant 8 upheld (no smart-formatting keys); vocab reuses the `additional_vocab` shape, ≤1000. Whole call bounded by `sttBatchResendTimeout` (120s [tune]) via `Deadline.run` in the caller. `WAVEncoder` (KoeCore, tested) wraps the headerless PCM16 tape for upload.
- **Retry loop**: coordinator catch maps `UnrecoveredUtterance` → `history.recordUntranscribedSession` (empty-rawText audit row; new `HistoryWriting` methods) + `RecoveryHandle(audioID:historyID:)` on the failed outcome/`utteranceFailed`. HUD failed-phase carries the handle: retry button (dwell `hudRetryDwell` 10s; the panel drops `ignoresMouseEvents` ONLY in this state), `startRetry` reserves a fresh FIFO ticket, replays the batch leg (`RecoveryRetrying` seam = `ResilientTranscriber`), on success deletes the audit row + WAV and runs the normal post-STT stages (shared `run(_:transcribe:failureRecovery:)` refactor). A failed retry re-surfaces the SAME handle. Stale (non-current) retryable failures lose the button (notice line can't host one) — P0 trade-off, row remains for M7-T2.
- **P0 scope notes**: `TempAudioStore` clears leftovers at launch (design allows discard-on-restart; the history row is the durable trail). Synthetic `startRecording/endRecording` transitions on retry keep the session lifecycle uniform for observers; metrics for retries are therefore approximate.

### M4-T3 high-effort code-review follow-up (9 findings; 8 CONFIRMED fixed, 1 cleanup applied)

- **Deletion moved to after full pipeline completion** (the review's top cluster): the first cut deleted the audit history row (and, inside `retryTranscribe`, the WAV) at batch-success — a downstream format/insert failure then re-surfaced a stale handle whose audio was gone, and a second tap silently lost already-recovered text. Now `retryTranscribe` never deletes; `startRetry` deletes the row and calls the new `RecoveryRetrying.discardRecovered` only on a `.completed` outcome. A failed retry keeps the same handle with its audio intact (a re-retry re-runs the batch call — accepted cost).
- **Retry double-fire closed at two layers**: `HUDReducer`'s `.began` now resets the phase to `.working` (the retry button can't outlive the retry it launched), and the coordinator keeps an `activeRetries` set — a duplicate `startRetry` for an in-flight audio id returns `nil` (`retry_duplicate_ignored`). - **Tape pump cancelled on streaming success / UnrecoveredUtterance** (it kept consuming the mic stream after early provider finalization), and `AudioTape` now wraps `SessionAudioBuffer` — the resend copy shares the session cap instead of duplicating an uncapped buffer.

## 2026-07-09 (session 13 — hotfix: WebSocket ping double-resume crash)

- **`URLSessionWebSocketChannel.ping()` crashed the app (SIGTRAP, `CheckedContinuation` double-resume) shortly after launch** — found by M9-T1 runtime verification, which noticed the process gone minutes after `pipeline_ready`, with matching `.ips` reports for every post-PR-B verification run (the bug became reachable once PR-B's launch prewarm exercised the real socket; before that, only the keyed live tests touched it). `URLSessionWebSocketTask.sendPing` can invoke its completion handler more than once when the pong races a concurrent socket failure, and `verify`'s `onCancel` teardown (`task.cancel`) widens exactly that window; the handler resumed the continuation unconditionally. ## 2026-07-09 (session 12 — full-codebase review, batch A: insertion)

Owner directive: review the entire codebase batch-by-batch (A–F), fix confirmed findings, no approvals. Batch A = PasteSimulator + KoeCore/Insertion + serializer + context provider + key resolver.

- **`runAppleScriptPaste` installs `terminationHandler` before `run()`.** A handler assigned after the process exits is never invoked — the continuation would stay suspended forever and stall the insertion FIFO (data-loss-class). Launch failure resumes the same continuation with `launched == false`; no double-resume is possible (a process that never ran can't fire the handler).
- **Paste choreography is now cancellation-safe.** `try? await Task.sleep` silently no-ops when the task is cancelled, collapsing the timing chain: a skipped pre-delay could post Cmd+V before the clipboard write propagates (pasting stale content); a skipped settle ran verify/restore too early. Now: cancelled pre-delay → `.advance` without posting (payload stays; the chain degrades to the clipboard landing, which posts nothing); the settle sleep is shielded in an unstructured child task so verify + marker-gated restore always complete once the keystroke is out (an early restore would paste the OLD content; skipping restore would permanently clobber the user's clipboard — review finding).
- **AX reads bounded via process-wide messaging timeout (`axReadTimeout`, 1s).** The ~6s system default let one unresponsive target app freeze the main actor (hotkeys, UI) for multi-second stretches per read. 1s, not the 250ms first tried: timed-out secure-field/verify reads fail *open* (proceed / assume success), so an aggressive bound silently weakens the invariant-3 secure guard and the invariant-1 verify net for slow-but-alive apps (heavy Electron ~400ms) — review finding. The system-wide `AXUIElement` is created once and reused.
- **Reviewed, accepted as-is (documented here as the audit trail):** `postCmdV` partial CGEvent-creation failure still reports success (unreachable in practice, and distinguishing "V-down failed" from "V-up failed" is what decides paste-vs-no-paste); re-entrancy guard returns `.clipboardFallback` without writing the clipboard (only reachable from DEBUG QA hooks — production is serialized by `InsertionSerializer`); verify false-negative → path-2 double-paste risk is the documented best-effort trade-off; `InsertionSerializer.complete` keeps its `precondition` (structural exactly-once release in the coordinator, unit-tested).

### Batch D — high-effort code-review follow-up (4 findings, all addressed)

The workflow review flagged that the initial timeout fix used `try? await Task.sleep` in the deadline race, which cannot tell a genuine timeout from caller cancellation. Extracted one shared, cancellation-correct primitive and converged both timeout races on it:

- **New `Deadline.run(_:onTimeout:operation:)` in KoeCore** (finding [3] cleanup — the LLM race and the Speechmatics ping-verify were duplicate copies of the same idiom). Semantics, now defined and unit-tested in one place: operation value passes through; an operation error propagates **unchanged** (never remapped to the timeout error); a real deadline throws `onTimeout()`; **caller cancellation propagates as `CancellationError`, not a false timeout** (the deadline sleep is `try await`, not `try?`). `SpeechmaticsClient.verify` now uses it (the ping's cancellation handler still tears the socket down on timeout).
- **Cancelled utterance no longer inserts** (finding [1] — the important one). Because the old race misclassified cancellation as `LLMError.timeout`, `LLMFormatter.format` would degrade-to-raw and the coordinator would then insert text the user had cancelled — once a future "cancel dictation" wires `Task.cancel()` to the utterance task (`DictationSession.CancelReason` already exists). `format` is now `async throws` and re-throws `CancellationError` (real LLM errors, incl. timeout, still degrade — invariant 2); the coordinator's `catch` turns that into a failed utterance that never reaches the insert stage.
- **`LLMClient.complete` documents a cancellation-responsiveness contract** (finding [2]) — the total-time bound is only as tight as the callee's cancellation response, so a future non-`URLSession` adapter (Bedrock/Haiku) must be cancellation-aware or it would stall the FIFO pipeline past the bound.
- **Test coverage for the classification** (finding [0]) — `DeadlineTests` asserts timeout-vs-passthrough-error-vs-cancellation directly (previously all error paths collapsed to the same `PipelineOutput`, so an inverted classification couldn't be caught); `LLMFormatterTests.cancellationAborts` asserts a cancelled format throws rather than returning a degraded output. 164 tests total.

## 2026-07-06 (session 11 — M5-T3 fallback chain + per-app overrides)

- **Chain ordering is pure and fault-injection-tested; system work is the adapter's.** `InsertionChain.run(paths, attempt:)` walks a plan and stops at the first `.landed`, with a `.clipboardFallback` floor; the per-path system work (paste / AppleScript / clipboard) is the app-layer `attempt` closure. This puts the reviewer's acceptance case — "block path 1 → walk to path 3" — into a KoeCore unit test with no system APIs. `InsertionPathPlanner.plan(preferred:)` always ends at `.clipboardOnly` so the chain can never fall off the end with text lost (invariant 1).
- **`InsertionChain.run` takes `isolation: isolated (any Actor)? = #isolation`.** The `attempt` closure captures the `@MainActor` `PasteSimulator`; a plain non-isolated static func would reject it as a data race (or force `@Sendable`, which then can't capture the test's mutable recording array). Inheriting the caller's isolation lets both the MainActor adapter and the non-isolated test drive it.
- **Path 2 runs `osascript` as a bounded subprocess, not `NSAppleScript` on the main thread.** `tell application "System Events" to keystroke "v" using command down` via `/usr/bin/osascript`, awaited through the process `terminationHandler`; a watchdog `Task { @MainActor }` terminates it if it overruns `insertionStageTimeout` (e.g. a blocked Automation-permission prompt) so the chain advances instead of hanging. Exit 0 = delivered. (App Sandbox is off, so `Process` is available; needs Automation TCC for System Events — owner QA.)
- **A failed path advances without restoring.** Write-fail / keystroke-post-fail / explicit verify-fail all return `.advance` and deliberately leave the marked payload on the clipboard so the next path (or the path-3 landing) still has the text. Restore only runs on a landed paste, and only if our session marker still owns the clipboard.

## 2026-07-06 (session 10 — M5-T2 paste simulation path 1)
