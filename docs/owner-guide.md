# オーナー作業手順書（Koe）

Claude Code が実装を自律で進めるなかで、**あなた（オーナー）にしかできない作業**をまとめた手順書です。コードの知識は不要です。上から優先順位順に並んでいます。

- コードレビューは不要です（品質は CI と自動レビューで担保）。
- あなたの役割は「アカウント/課金/規約」「API キー取得」「実機での動作確認（QA）」「日々の試用（ドッグフーディング）」です。

---

## 0. 用語と前提

- **API キー**: 各 AI サービスを使うためのパスワードのような文字列。これがないと「実際に喋って入力する」機能が作れません。
- **Keychain（キーチェーン）**: macOS が秘密情報を安全に保管する仕組み。API キーはここに入れます。
- キーは**あなたの手元でコマンドを実行して直接 Keychain に入れます**（Claude にキー本体を見せない安全な方法）。

---

## 1.【最優先】API キーを2つ用意する（Gemini + Speechmatics）

この2つが揃うと「録音 → 整形 → 挿入」の最初の縦1本を通せます。残りのプロバイダ（Deepgram / Soniox / AWS）は Phase 0 の比較検証用で、**後回しで構いません**（→ 第2節）。

> 費用の目安: どちらも従量課金（使った分だけ）。無料トライアル枠で初期テストは十分まかなえます。ヘビーに使っても月あたり数百円〜1,000円程度の想定です。

### 1-A. Gemini（整形用 LLM・主選定）

1. ブラウザで **https://aistudio.google.com** を開き、Google アカウントでログイン。
2. 左メニューまたは右上の「**Get API key**（API キーを取得）」を開く。
3. **課金（有償 tier）を有効にする**のが重要です（無料枠のままだと入力内容が学習に使われる可能性があります）。
   - 「Create API key」時に **Google Cloud プロジェクト**を選ぶ/作る画面が出ます。そのプロジェクトで**課金（Billing）を有効化**してください（クレジットカード登録）。
   - 課金を有効化したプロジェクトに紐づくキーが「有償 tier ＝ 学習不使用」になります。
4. 表示された **API キー文字列**（`AIza...` のような文字列）をコピー。
5. ターミナルで、下のコマンドの `ここにキー` を貼り替えて実行します。このチャットに `!` を付けて打つとこのセッション内で実行できます:

   ```
   ! security add-generic-password -s dev.newt.Koe -a geminiAPIKey -w 'ここにキー' -U
   ```

### 1-B. Speechmatics（音声認識 STT・主選定）

1. ブラウザで **https://portal.speechmatics.com** を開き、アカウント登録（無料トライアルあり）。
2. ログイン後、ポータル内の「**API Keys**」でキーを新規発行し、文字列をコピー。
3. ターミナルで実行:

   ```
   ! security add-generic-password -s dev.newt.Koe -a speechmaticsAPIKey -w 'ここにキー' -U
   ```

> 補足: Speechmatics は利用規約に「学習利用」の条項があり、公式ドキュメントの「保存しない」記述と表面上矛盾しています。**個人でのドッグフード段階では問題ありません**が、将来の外部配布（Phase 2）前に書面確認が必要、と設計書に記録済みです。

### 1-C. 保存できたら Claude に伝える

キーを2つとも入れ終えたら、チャットで「**Gemini と Speechmatics のキーを入れた**」と伝えてください。Claude がアダプタ（M4 STT / M6-T1 LLM）を実装し、実際に動くか検証します。

> 初回にアプリ/検証ツールがキーを読む際、**キーチェーンのアクセス許可ダイアログ**が出ることがあります。その場合は「**常に許可**」を選んでください。

## 2. Phase 0 の比較検証用キー（後回しでOK）

音声認識・LLM を実測で最終決定する Phase 0 の A/B 比較で使います。**縦1本が動いてからで構いません。**

| プロバイダ | 用途 | 登録先 | 保存コマンドのアカウント名（`-a`） |
| --- | --- | --- | --- |
| Deepgram | STT 次点 | https://console.deepgram.com | `deepgramAPIKey` |
| Soniox | STT 低コスト候補 | https://console.soniox.com | `sonioxAPIKey` |
| AWS Bedrock | LLM 次点（Claude Haiku・東京） | AWS アカウント | `awsAccessKeyID` と `awsSecretAccessKey`（2つ） |

保存コマンドは 1-A と同じ形（`-a` を上表の名前に変える）:

```
! security add-generic-password -s dev.newt.Koe -a deepgramAPIKey -w 'ここにキー' -U
```

> **AWS Bedrock** はやや手間です（AWS アカウント作成 → Bedrock で Claude Haiku のモデルアクセスを **ap-northeast-1（東京）** で申請 → IAM ユーザーを作りアクセスキー2つを発行）。必要になったら Claude が個別に手順を出します。今は不要です。

## 3. Phase 0 の音声サンプル録音（STT 比較用）

音声認識3社を同じ音声で比較するため、**あなたの声で短い発話を約100本**録音してもらいます（純日本語50・日英混在30・辞書語20）。

- 読み上げる台本リストは Claude が用意します（「S2 の台本を出して」と言えば出します）。
- 録音は静かな環境で、普段の話し方で。詳細な手順（録音アプリ・形式）は台本と一緒に案内します。
- **これも縦1本が動いてからで構いません。**

## 4. 実機での動作確認（QA）— アプリができてきたら

Claude はコードを書きテストを通しますが、**実際のアプリでの動作確認はあなたの担当**です。マイルストーンごとに Claude が「日本語のチェックリスト」を用意するので、その通りに触って結果（OK / ダメだった点）を返してください。

- **今すぐできる確認（現状のアプリ骨組み）**:
  ```
  ! cd "仕事 v3/typeless-clone" && xcodegen generate && open Koe.xcodeproj
  ```
  Xcode で ▶（Run）→ メニューバーにマイクのアイコンが出て、メニュー（History / Settings / Pause / Quit）が開けば OK。
- **権限ダイアログ**: 今後ホットキーや録音の機能が入ると、macOS が「マイク」「アクセシビリティ」の許可を求めます。出たら許可してください（オンボーディングで Claude が案内します）。

## 5. 節目でのレビュー起動（あなたが打つ）

品質の深いレビューは課金付きのクラウドレビューで行います。**Claude からは起動できない**ため、Claude が「今このコマンドを打ってください」と促したタイミングで、あなたがチャットに入力してください。

- マイルストーン完了時（特に挿入 M5・整形 M6・Phase 1 完了時）:
  ```
  /code-review ultra
  ```
- 外部配布の前（Phase 2）:
  ```
  /security-review
  ```

## 6. 日々の試用（ドッグフーディング）— Phase 1 の最終品質判定

アプリが「喋って入力できる」状態になったら、**毎日の実業務（メール・Slack・Claude Code への指示など）で実際に使ってください**。これが最終的な品質判定（手直しの少なさ・手放せないか）になります。気づいた不満は何でもチャットで伝えてください。
